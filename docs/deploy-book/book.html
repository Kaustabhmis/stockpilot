DOME BOX · BISCS INDIA
The Deploy Book

How to put the new Dome Box online.
Simple words. One step at a time. Pictures for every screen.

How to use this book. Read one step. Do it. Tick the box ☐. Then go to the next step. Do not skip steps. Do not do two steps at once. The pictures are drawings of the screens — your screen may look a little different, but the buttons have the same names. Red numbers show what to click, in order.

Chapter 0 — What you already have

You already have two Google Sheets. And every customer has their own sheet with their tasks.

The three rules of this book

1. Old script: leave it.The old script inside your Master sheet is your live website. Customers use it right now.
2. Customer sheets: never edit.The new script upgrades them safely. You never open them.
3. New script: own project.Made at script.google.com in Step 3. Not inside a sheet.

Words used in this book

WordMeaning
IDThe long code in a sheet's web address — the sheet's roll number. See Step 1.
ScriptThe program. Your file code.gs is a script.
ProjectA box that holds scripts.
RunPress the ▶ Run button to make the script do one job.
LogThe messages the script writes after Run. They appear at the bottom.
Script PropertiesA small settings list inside the project — like a notebook.

What you need

  • A computer with Google Chrome
  • Logged in to Google with the account that owns info@biscsindia.com
  • The file dome-box-complete.zip, unzipped into a folder
  • Your Netlify login, your Razorpay login, your GitHub login
  • Notepad open, to write down codes
  • About 2 hours, with no hurry

There are two parts. Part 1 — Practice: you build the new system next to the old one and test it. Customers notice nothing. Part 2 — Switch: you point the new system at your real Master sheet and move the website (about 45 minutes).

PART 1 — PRACTICE

Customers notice nothing. Nothing real is changed.

We practise on a new, empty sheet so the real customer list stays safe.

  1. Go to sheets.google.com → click Blank (the big +).
  2. Click Untitled spreadsheet at the top and type PRACTICE Master.
  3. Copy its ID like in Step 1. In Notepad: Practice ID =

3Make the NEW script project

  1. Go to script.google.com. Click New project 1.
  2. Click Untitled project 2 and name it Dome Box NEW.
  3. Click inside the code, press Ctrl + A then Delete 3.
  4. On your computer open the zip folder → dist → code.gs with Notepad. Ctrl + A, Ctrl + C.
  5. Back in the browser click inside the empty code area and press Ctrl + V.
  6. Click 💾 Save 4.
❗ You did this at script.google.com — NOT inside your Master sheet. That is correct.
Dome Box NEW has the long code in it, saved, with no red lines.

4Fill in the settings notebook

  1. On the left, click the ⚙ gear (Project Settings) 1.
  2. Time zone → choose (GMT+05:30) India Standard Time 2.
  3. Scroll down to Script Properties → Add script property 3. Add these rows:
Property (left box)Value (right box)

Seven rows saved. Time zone is India.

5Run the setup check

  1. Click <> Editor on the left.
  2. In the function box at the top 1 choose setupDomeBox.
  3. Click ▶ Run 2.
  4. Google asks for permission (Picture 6): Review permissions → your account → Advanced → Go to Dome Box NEW (unsafe) → Allow. It says “unsafe” only because you made the app yourself.
  5. Read the Execution log at the bottom 3. Some lines say ok, some say MISSING. That is normal now — the next steps fix them.

6. Go back to ⚙ Project Settings. A new row AUTH_PEPPER has appeared. Copy its value into Notepad and keep it forever. If it is lost, every customer must reset their password.

setupDomeBox ran. AUTH_PEPPER is in Notepad.

6Let it send emails from info@biscsindia.com

Only if the log says not a verified send-as alias:

  1. Open Gmail → ⚙ → See all settings → tab Accounts and Import.
  2. Send mail as → Add another email address → type info@biscsindia.com → follow the steps.
  3. Open the email Google sends and click the link inside it.
  4. Back in the script: run setupDomeBox again.
The log says: every email will leave from info@biscsindia.com

7Put the new script on the internet

  1. Top right: Deploy 1 → New deployment 2.
  2. Click the ⚙ next to Select type → Web app 3.
  3. Execute as: Me. Who has access: Anyone 4. Click Deploy.
  4. Copy the Web app URL that ends with /exec 5. In Notepad: API URL =
Later, whenever you change the code: Deploy → Manage deployments → ✏ pencil → Version: New version → Deploy. Just pressing Save is not enough.
I have the API URL in Notepad.

8Add the reminders file

A second file in the same project. It sends the 9 am, 3 pm and 5 pm reminders and makes repeating tasks.

  1. Next to Files click + → Script 1. Name it reminders.
  2. Delete what is inside. Paste all of domebox → reminders.gs from the zip.
  3. Near the top change two lines 2 (see picture): put your Practice ID inside the quotes after SHEET_ID:, and change DRY_RUN: true to DRY_RUN: false.
  4. 💾 Save. Choose installDomeBoxSchedules → ▶ Run.
  5. Choose setupDomeBox → ▶ Run.
❗ Never add the file payments-secure.gs. It is old and breaks payments.
The log says: all scheduled jobs are installed (task reminders at 9, 15 and 17)

9Connect Razorpay — in TEST mode

❗ Do not regenerate your live keys now. Your old system collects real payments with them. In the practice run you use Razorpay's Test Mode — pretend money, separate keys. Live keys are only touched on switch day (Steps 18 and 20).
  1. Razorpay Dashboard → top of the screen, switch Live Mode → Test Mode 1.
  2. Account & Settings → API Keys → Generate Test Key. Copy the Test Key ID (starts with rzp_test_) and Key Secret.
  3. Make up a long password, e.g. dbx-Hq27-Kolkata-91. In Notepad: Webhook secret =
  4. Script → ⚙ Project Settings → Script Properties → add:
PropertyValue
RAZORPAY_KEY_IDthe Test Key ID (rzp_test_…)
RAZORPAY_KEY_SECRETthe Test Key Secret
RAZORPAY_WEBHOOK_SECRETthe password you made up
SELLER_GSTINyour GST number (skip if not GST registered)

5. Still in Test Mode: Webhooks → Add New Webhook → URL = your API URL, Secret = the made-up password, tick payment.captured, Create.

6. Run setupDomeBox again. In Step 11 you can buy a plan on the practice site with a Razorpay test card — no real money moves.

No Razorpay line says MISSING. Test keys are in, live keys untouched.

10Make a practice website on Netlify

  1. app.netlify.com → Add new site → Import an existing project → GitHub → choose stockpilot.
  2. Fill the boxes exactly as in Picture 10.
  3. Add environment variables: API_URL = your API URL, and ALLOW_MISSING_LEGAL = 1 (only for practice — Step 15 removes it).
  4. Click Deploy. Wait until it says Published. Click the link ending in .netlify.app.
The practice website opens.

11Test it like a customer

  1. On the practice website, Sign up a test company with a second email address you own.
  2. Add one team member. Assign them a task.
  3. Log out. Log in again.
  4. Check your email: did the welcome email come from info@biscsindia.com?
Sign up, login, task and email all work.

🎉 Part 1 is done. Customers are still on the old system and noticed nothing.

PART 2 — THE SWITCH

About 45 minutes. Do it on a quiet day, for example Sunday evening.

12Copy your Master sheet (safety copy)

  1. Open your real Master sheet → File → Make a copy.
  2. Name it Master BACKUP and today's date. Do not use this copy for anything — it is only for safety.
Master BACKUP exists.

13Point the NEW script at your REAL Master sheet

  1. Dome Box NEW → ⚙ Project Settings → Script Properties → MASTER_DB_ID → change it from the Practice ID to your real Master ID (Step 1). Save.
  2. Open the reminders file → change SHEET_ID to the same real Master ID. Save.
  3. Choose ensureRegistry → ▶ Run. (It only adds missing tabs. It never deletes.)
This does not change your old script. It only tells the new script where the real customer list is.
Both places have the real Master ID.

14Back up every customer's sheet

  1. Files + → Script → name it backup. Paste all of domebox → backup.gs. Save.
  2. Choose backupAllTenants → ▶ Run. Wait. It makes a copy of every customer's sheet in a Drive folder called Dome Box Backups.
  3. Choose verifyLatestBackup → ▶ Run. Every company should have a good copy.
Many customers? If the log says Hit MAX_PER_RUN, just run backupAllTenants again — it skips the ones already copied today.
verifyLatestBackup shows no “NO BACKUP AT ALL”.

15Fill in your company details for the website

  1. github.com → your repository stockpilot.
  2. Click the branch button that says main 1 → choose claude/obfuscated-html-content-aywe2k.
  3. Open folder netlify → file site-config.json → click the ✏ pencil 2.
  4. Fill every empty "" 3: address, phone, GSTIN, entity type (e.g. Proprietorship), registration number, grievance officer's name, city, state.
  5. Click Commit changes 4.
  6. Netlify (practice site) → Site configuration → Environment variables → delete ALLOW_MISSING_LEGAL.
  7. Deploys → Trigger deploy → Deploy site.
It says Published, and the footer links (Privacy, Terms, Refund, Contact) open.

16Preview the upgrade (changes nothing)

  1. Choose previewMigration → ▶ Run. Read the log. It lists every customer.
  2. If there is a section NEEDS A LOOK: someone added an extra column by hand to that company's sheet. The log says which column and where. Move that column to the far right of their Tasks tab, then run previewMigration again. Repeat until NEEDS A LOOK is gone.
previewMigration shows no NEEDS A LOOK.

17Do the upgrade

  1. Choose migrateAllTenants → ▶ Run.
  2. Every company should be under UPGRADED or ALREADY CURRENT.

Customers keep their own sheets. Nothing is deleted. New columns and tabs are only added.

Every company is UPGRADED or ALREADY CURRENT.

18Give the new script your CURRENT live Razorpay key

For the switch, the new script uses the same live key your old system uses today. Nothing changes in Razorpay yet, so payments never stop.

  1. Open your Master sheet → Extensions → Apps Script (the OLD script). Press Ctrl + F and search rzp_live. Copy the Key ID and the Key Secret next to it. Change nothing, close the tab.
  2. Dome Box NEW → ⚙ Project Settings → Script Properties → replace the test RAZORPAY_KEY_ID and RAZORPAY_KEY_SECRET with these live ones. Save.
  3. Razorpay Dashboard → switch to Live Mode → Webhooks → Add New Webhook: URL = your new API URL, Secret = your made-up password, tick payment.captured, Create.
  4. Run setupDomeBox.
The new script has the live key. Razorpay has a live webhook to the new API URL.

19Move www.domebox.in to the new website

  1. Netlify → your OLD site → Domain management → remove www.domebox.in and domebox.in.
  2. Your NEW site → Domain management → Add a domain → www.domebox.in, then domebox.in.
  3. Wait for the 🔒 HTTPS certificate (up to an hour).
  4. Open www.domebox.in and log in with your existing account and password.
If something goes wrong: put the domain back on the OLD site. Your old script is still there, untouched. Keep it for one week before deleting anything.
www.domebox.in shows the new site, and your old login works.

20Replace the old Razorpay key with a new one

The old key was written inside the old code, so anyone who ever saw that code could use it. Now that the website runs on the new script, replace it.

  1. Razorpay Dashboard → Live Mode → Account & Settings → API Keys → Regenerate. If Razorpay asks when the old key should stop, you may choose immediately — nothing uses it any more.
  2. Copy the new Key ID (rzp_live_…) and Key Secret.
  3. Dome Box NEW → ⚙ Project Settings → replace RAZORPAY_KEY_ID and RAZORPAY_KEY_SECRET. Save. Run setupDomeBox.
  4. Razorpay → Webhooks: if there is an old webhook pointing to the old script's address, delete it. Keep the new one.
  5. Buy the cheapest plan once on www.domebox.in with a real card to be sure, then refund it from the Razorpay Dashboard.
Do this after Step 19, never before. If you regenerate while the old site still has the domain, the old site's payments stop.
New live key in. Old key replaced. One real test payment worked.

21Close the old “anyone with the link” sharing

  1. Files + → Script → name it sharing. Paste all of domebox → remediate-sharing.gs.
  2. At the top find MASTER_DB_ID: '…'. Make sure the ID inside the quotes is your real Master ID. Save.
  3. Choose auditSharing → ▶ Run. It only looks.
  4. Change DRY_RUN: true to DRY_RUN: false. Save. Choose lockDownAllTenants → ▶ Run.
  5. Run auditSharing again.
auditSharing shows nothing shared publicly.

22Tell your customers

Open MIGRATING-CUSTOMERS.md from the zip. Copy the ready email and send it. Customers log in with the same email and password.

Email sent.

23One week later

  1. Run previewTaskArchive, read it. Then archiveOldTasks. Then installTaskArchiveSchedule once. (Tasks finished over a year ago move to a tab called Tasks_Archive in each customer's own sheet.)
  2. Run createDemoAccount for sales calls. It prints the login.
  3. On GitHub, merge Pull Request #2 into main.

🎉 Finished!
